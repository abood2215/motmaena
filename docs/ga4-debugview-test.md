# اختبار أحداث GA4 يدوياً عبر DebugView

يشرح هذا الملف كيف نتأكد يدوياً أن الأحداث الأربعة الجديدة تصل إلى GA4، وما النتيجة المتوقعة لكل حدث.

## قبل البدء
- **مكان الاختبار:** الموقع الحقيقي فقط (`motmaena.motmaina-center.com`) بعد النشر.
  - النسخة المحلية والنسخ التجريبية لا ترسل شيئاً، وهذا مقصود.
  - على السيرفر يجب أن تكون قيمة `APP_ENV` هي `production`.
- **المتصفح:** Chrome على الكمبيوتر.
  - أوقف مانع الإعلانات (AdBlock وما يشبهه) لهذا الموقع.
- **تشغيل وضع الفحص:** بإحدى طريقتين:
  - إضافة **Google Analytics Debugger** من متجر Chrome، وتفعيلها.
  - أو فتح **tagassistant.google.com**، ثم Add domain، ثم إدخال رابط الموقع.
- **فتح DebugView:** في GA4 من Admin ← Data display ← DebugView. اختر جهازك من قائمة Debug devices.
  - قد يتأخر ظهور الأحداث 10 إلى 30 ثانية.

## الحدث 1: مشاهدة الدورة (`view_item`)

**الخطوات:** افتح صفحة أي دورة، مثل `/register/psychological-first-aid`، أو صفحة العرض المشترك `/register/bundle/november-courses`.

**يظهر في DebugView:** `view_item` مرة واحدة عند فتح الصفحة.

| المعامل | صفحة دورة | صفحة العرض المشترك |
|---|---|---|
| `content_type` | `course` | `bundle` |
| `content_name` | اسم الدورة بالعربي | `november-courses` |
| `content_ids` | رمز الدورة، مثل `psychological-first-aid` | `november-courses` |
| `value` / `currency` | سعر الدورة / `KWD` | سعر العرض / `KWD` |

## الحدث 2: الضغط على التسجيل (`register_click`)

**الخطوات:** من الرئيسية أو صفحة الدورات، اضغط على أي زر أو بطاقة تفتح صفحة تسجيل، مثل "احجز مقعدك" أو "الدورتان معاً".

**يظهر في DebugView:** `register_click` مرة لكل ضغطة.

| المعامل | النتيجة المتوقعة |
|---|---|
| `content_type` | `course` أو `bundle` |
| `content_name` و`content_ids` | رمز الدورة أو العرض، مثل `communication-skills` |
| `link_location` | مكان الزر (انظر الجدول في آخر الملف) |

## الحدث 3: بدء الدفع (`begin_checkout`)

**الخطوات:** في صفحة دورة، عبّئ النموذج ثم اضغط زر الدفع. **توقف عند صفحة الدفع ولا تدفع.**

**ملاحظات قبل الاختبار:**
- هذه الخطوة تُنشئ تسجيلاً "غير مدفوع" في لوحة التحكم.
- استخدم اسم "اختبار" ورقم الفريق ليسهل تمييزه لاحقاً.
- يُحسب الحدث عند الضغط على زر الدفع، حتى لو رفض النموذج البيانات بعدها.

**يظهر في DebugView:** `begin_checkout` مرة واحدة قبل الانتقال لصفحة الدفع.

| المعامل | صفحة دورة | صفحة العرض المشترك |
|---|---|---|
| `value` / `currency` | المبلغ بعد الخصم / `KWD` | سعر العرض / `KWD` |
| `content_type` | `course` | (لا يُرسل) |
| `content_name` | اسم الدورة بالعربي | `november-courses` |
| `content_ids` | رمز الدورة | (لا يُرسل) |

## الحدث 4: الضغط على واتساب (`contact`)

**الخطوات:** اضغط على أزرار واتساب في أماكن مختلفة: الزر العائم، والفوتر، وأزرار الصفحات.

**يظهر في DebugView:** `contact` مرة لكل ضغطة.

| المعامل | النتيجة المتوقعة |
|---|---|
| `content_name` | `whatsapp` |
| `link_location` | مكان الزر، ويختلف حسب الزر الذي ضغطته |

## يجب ألا يظهر في أي حدث
- الاسم، أو الهاتف، أو الإيميل، أو الملاحظات، أو نوع الاستشارة.
- نص رسالة الواتساب، أو رابط الواتساب نفسه.

إذا ظهر أي منها، أوقف الاختبار وبلّغ فوراً.

## قيم `link_location`

| الصفحة | القيم |
|---|---|
| كل الصفحات | `header`، `footer`، `floating` (الزر العائم) |
| الرئيسية | `top-banner`، `november-courses`، `courses`، `visit-center`، `final-cta`، `sticky-bar` (الشريط السفلي في الموبايل) |
| الاستشارات | `hero`، `steps`، `final-cta`، `sticky-bar` |
| الجلسات | `hero`، `plans`، `installments`، `special-needs`، `final-cta` |
| الباقات | `hero`، `packages-section` |
| صفحة الدورة | `course-page` |
| صفحة الدورات | `live` |

## بعد الاختبار
- **لإظهار المعاملات في تقارير GA4 العادية** (لا تحتاجها DebugView): سجّل مرة واحدة 3 Custom dimensions بنطاق Event من Admin ← Custom definitions:
  - `link_location`
  - `content_name`
  - `content_type`
- **احذف أو علّم التسجيل التجريبي** في لوحة التحكم.
